# mikrotik-gre-ospf-bgp

Эталонные конфигурации трёх маршрутизаторов MikroTik: 
центральный узел (ЦУ) и два филиала (все адреса обезличены, любые совпадения случайны).

# Примечание 
Заменить ether1 / ether2, адрес шлюза и публичные адреса на свои.
Загрузить файл на роутер и выполнить /import file-name=<имя файла>.rsc.
Задать ключ IPsec на каждом GRE-интерфейсе.
Проверить результат.

# Используемые технологии
| Параметр | Значение |
|---|---|
| OSPF | единая backbone-область, тип сети |
| BGP | iBGP, AS 65530, пиринг по loopback'ам , `multihop=yes` |
| Топология BGP | каждый с каждым |

##               Топология
 
```
                    ЦУ
        WAN 203.0.113.1   lo 10.254.0.1
        LAN 10.10.0.0/24
          /                      \
  172.16.1.0/30              172.16.2.0/30
        /                          \
   Филиал 1 ------------------- Филиал 2
 WAN 198.51.100.1   172.16.3.0/30   WAN 192.0.2.1
 lo 10.254.0.2                      lo 10.254.0.3
 LAN 10.20.0.0/24                   LAN 10.30.0.0/24
```


Три узла соединены кольцом GRE-туннелей. 
Поверх них работают OSPF (достижимость loopback и линков) и iBGP (обмен LAN-префиксами).

## Туннели и линковые сети
 
| Линк | Подсеть | Сторона A | Сторона B | MTU | Стоимость OSPF |
|---|---|---|---|---|---|
| ЦУ ↔ Филиал 1 | 172.16.1.0/30 | ЦУ 172.16.1.1 | Ф1 172.16.1.2 | 1398 | 10 |
| ЦУ ↔ Филиал 2 | 172.16.2.0/30 | ЦУ 172.16.2.1 | Ф2 172.16.2.2 | 1398 | 10 |
| Филиал 1 ↔ Филиал 2 | 172.16.3.0/30 | Ф1 172.16.3.1 | Ф2 172.16.3.2 | 1398 | 100 |

## Маршрутизация
 
| Узел | BGP-пиры | Анонсируемый префикс |
|---|---|---|
| ЦУ | 10.254.0.2, 10.254.0.3 | 10.10.0.0/24 |
| Филиал 1 | 10.254.0.1, 10.254.0.3 | 10.20.0.0/24 |
| Филиал 2 | 10.254.0.1, 10.254.0.2 | 10.30.0.0/24 |
 
## Адресные списки
 
| Список | Содержимое | Назначение |
|---|---|---|
| `filials` | публичные IP двух других узлов | разрешение трафика от/к узлам |
| `vpn_ext` | 192.168.100.0/24 | внешние VPN-клиенты, доступ только к LAN своего узла |
| `bgp_networks` (только ROS 7) | LAN узла | источник префиксов для BGP |
 
## Логика решений
 
| Решение | Почему |
|---|---|
| Полная сетка туннелей | отказ любого одного линка не рвёт связность, трафик идёт через третий узел |
| Стоимость 100 на линке между филиалами | при живом ЦУ трафик идёт через него, прямой линк служит резервом |
| iBGP по loopback'ам | сессия не зависит от состояния отдельного туннеля |
| Без route reflector | при трёх узлах и полной сетке он не нужен (использовался в полной топологии)|
| Единый MTU 1398 | запас под заголовки GRE и IPsec, совпадение MTU на обоих концах нужно OSPF |
